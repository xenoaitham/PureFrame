# PureFrame Speed Offensive - "90-min movie in ~10-20 min"

**Scope:** All profiles (CPU through HIGH) · **Gate:** every change must hold `pureframe evaluate` F1 within noise · **Validation:** mocked tests + CI only; no model loads on your machine (you run final benchmarks after the memtest).

## Why it's slow today (verified in code)

1. `extract_frames` re-decodes **from frame 0** for every shot (no `-ss` seek) - a shot at minute 60 decodes an hour of video to grab 2 frames. Near-quadratic; the dominant cost.
2. CPU/LOW profiles **reload the NudeNet ONNX model once per densified frame** (`nudity.py:76` unloads after every `detect_batch`; `densify.py:31` calls it per frame → dozens of full model re-inits per shot).
3. CLIP + PANNs run **eagerly per shot** even when NudeNet is decisive and `fuse` ignores them (`fuse.py:58-66` short-circuits first).
4. `detection_batch_size` is **dead config** (zero consumers); `use_fp16` only affects CLIP.
5. Scene detection decodes every frame at full framerate (no `frame_skip`).
6. Render: no x264 preset (ffmpeg `medium` default), 4-5 subprocess spawns + 2 probes per dirty segment, `ffmpeg -encoders` re-parsed per segment, double colorspace conversion + 2 numpy copies per dirty frame.
7. Kiss shots extract **every frame** with a from-0 decode each.
8. No repeatable benchmark: `run_benchmarks.sh` expects a clip nothing generates; `scripts/bench.py` regenerates BENCHMARKS.md with stale numbers.

## Phase 0 - Benchmark harness first (so every win is provable)

- New `pureframe bench` command: generates a reproducible synthetic clip **with scripted skin regions that genuinely trigger NudeNet** (current bench clips have zero detections, which is why numbers lie), runs all profiles × N reps, prints **per-phase timers** (scene/sample/detect/densify/context/fuse/render/encode), emits JSON + Markdown rows for BENCHMARKS.md, captures environment info.
- Instrument phase timers in `cli.generate_plan`/`execute_render` (cheap `time.perf_counter()` accumulators, printed in `--verbose` and always in bench mode).
- **Eval-parity CI job**: `pureframe evaluate` is deterministic + CPU-runnable → run it in CI on every PR and fail if F1 drifts beyond ±0.02 of a committed `eval-baseline.json`. This makes your "parity" gate automatic.
- Delete stale `scripts/bench.py` (dangerous: overwrites BENCHMARKS.md with numbers contradicting `hardware.py`).

## Phase 1 - Algorithmic fixes (biggest wins, all profiles)

1. **Seek-based extraction** (`sample.py`): input-seek `-ss` to the shot window, select relative frame indices, pass video metadata in (cache one `probe` per plan, not per call). Parity test: old vs new extraction returns pixel-equal frames on synthetic clips (half-frame epsilon for keyframe alignment).
2. **Fix the per-batch model reload** (`nudity.py`): `keep_models_loaded` governs end-of-plan unload only - never between `detect_batch` calls. One-line fix, massive effect on CPU/LOW.
3. **Lazy context models**: add `fuse.needs_context(nudity_dets, thresholds)` mirroring fuse's decision boundaries; `cli.generate_plan` skips CLIP + PANNs when NudeNet's verdict is already decisive. Record `"reasoning": "skipped: NudeNet decisive"` for transparency. Expected to cut context-model cost ~90% on typical content.
4. **Scene-detection `frame_skip`**: new `ProfileSettings.scene_frame_skip` (2 on LOW/CPU, 1 on HIGH/MEDIUM), wired into PySceneDetect; boundaries stay within ±1 frame.
5. **Kiss-shot cap**: full-frame extraction respects `densify_every_n_frames` instead of every frame.
6. **Render overhead**: cache `_get_fps` + `select_hw_encoder` once per render (currently re-probed/re-parsed per dirty segment); eliminate one numpy copy per frame (blur in place, write memoryview).

## Phase 2 - Render path

7. **Encoder presets** per profile (new `ProfileSettings.encoder_preset`): `veryfast` on CPU, `faster` elsewhere; NVENC gets `-preset p4` + explicit `-rc`/`-cq` (currently only `-crf`, which NVENC often ignores). 2-3× encode speedup, free.
8. **Pure-ffmpeg overlay for BOX/PIXELATE modes**: single ffmpeg invocation per dirty segment using `drawbox`/`scale` with `enable='between(t,..)'` windows - no Python round-trip at all. BLUR mode keeps the Python callback (blur needs the OpenCV kernel); it now only round-trips dirty frames, which smart render already ensures. Preserves `frame_actions` dict shape (pinned by `tests/test_render.py`).

## Phase 3 - Concurrency

9. **Pipelined plan generation**: extraction worker thread (ffmpeg subprocesses, I/O-bound) overlapping inference (ONNX releases the GIL during `Run`); bounded queue; results applied to checkpoints in shot order on the main thread. Deterministic, checkpoint-compatible. Expected ~1.5-2× overlap on all profiles.

## Phase 4 - Model-level (the portfolio centerpiece)

10. **ONNX int8 dynamic quantization of NudeNet on the CPU profile** - quantize once, cache in the platformdirs cache dir, `--no-quant` escape hatch, **eval-parity gate in CI proves detection quality holds**. Typically 2-4× CPU inference.
11. **ORT SessionOptions tuning**: `intra_op_num_threads` = physical cores, sequential execution, measured.
12. **Audio context cap**: PANNs analyzes the center 10 s of long shots (already per-shot segments; cost currently scales with shot length) + only ambiguous shots from Phase 1.

## Phase 5 - Docs & portfolio narrative

13. `docs/performance.md`: the profiling story - from-0 decode discovery, per-frame model-reload bug, lazy context gating, quantization with eval gates, before/after tables per profile. This is the resume narrative.
14. README performance section, ROADMAP check-offs (cached inference, time estimator), fresh BENCHMARKS.md. Final local benchmark run: **you**, after memtest86+ passes.
